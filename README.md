# STM32 电机考核工程

目标为 STM32F407VET6。默认 M3508/C620、CAN ID 1，修改电机类型后必须重新编译。
保留既有 USART1（PB6/PB7、115200 8N1）、CAN1（PA11/PA12、1 Mbps）和 LED0（PE7）配置。

现场接线、烧录、上位机设置、各任务验收及故障恢复见
[详细上板测试流程](C:/Users/32415/Downloads/大作业/motorcontrol/上板测试流程.md)。

## 协议与运行行为

- 接收仍为 `AA BB mode int16_A int16_B CRC8`，反馈仍为
  `BB AA status int16_speed int16_position CRC8`，均为 8 字节、小端参数。
- CRC8 多项式 0x07，初始值和异或值为 0，不反转。模式仍为 00/11/22，
  动作 ID 仍为 00000000/11111111；无需替换上位机。
- 循环 DMA 使用 256 字节接收缓冲；1 kHz 控制任务复制新数据并完成找帧头、CRC、
  语义检查。中断只标记 UART 错误，不解析或阻塞恢复。
- 正常指令刷新连接计时。400 ms 无有效指令判定断联；上位机建议按默认 100 ms 周期发送。
  坏 CRC/杂字节被丢弃且不续期；CRC 正确但未知模式/动作 ID 会使当前命令失效并停机。
- RX 启动失败每 10 ms 重试；UART/DMA 错误在线程内恢复收发两侧；TX 忙超过 50 ms 也恢复。
  DMA 轮询间隔超过 10 ms 时丢弃可能已被覆写的数据并等待新帧。
  未完成帧间隔达到 20 ms 时丢弃，避免拼接拔插前后的半帧。
- 运行中断联、传输故障或控制周期间隔达到 5 ms 后，保持零电流，清除控制器状态并锁定故障。
  连接恢复后先点击上位机已有的“急停”（速度模式 A=0、B=0），再发送运动指令。
  直接重发旧运动指令不会自动恢复运动。LED0 指示有效上位机连接，独立于电机故障状态。
- 沿用 AA/AF、BA/BF 反馈进度；FF 表示故障或等待急停确认，不新增状态码。
  普通目标连续满足容差 50 ms 才报告到达。位置动作在目标范围外会重置停留计时；
  速度动作完成时间序列后还需连续 50 ms 满足零速容差。
- 预设动作相同 ID 的周期帧不会反复重启动作。需要重做同一个动作时，先切换到普通模式，
  再发送该动作 ID。
- 第一帧有效 CAN 反馈建立上电零点，初始化完成且在线后才允许控制。
  CAN 反馈超时门限为 20 ms；重连后未知圈数不会被猜测，位置有效性保持锁定，
  本应用要求重启主控建立新的上电零点。恢复通信不能恢复未知的原绝对位置。
- C620/C610 最终电流指令上限分别为 8000/4000；动态电流上限同时参与 PID 抗积分饱和。
  控制器启停重置 PID；零电流急停不等于机械抱闸，实际停转时间必须上板测量。
- 内部角度保持连续累计；8 字节反馈的位置只能表达 -32768～32767°，超出时饱和显示，
  不回绕为反号。速度反馈同样饱和；要传完整多圈大角度需双方另行扩展协议。

## 编译

先准备 CubeMX 生成的 Core/Drivers/Middlewares 和 ARM GCC、CMake、Ninja。
仓库保留了原有的生成文件忽略规则，跨电脑交付时应包含这些目录，或先由 IOC 重新生成。
依赖集成通过 `cpkg sync --offline` 更新（缓存已准备好时）；不要手改生成的模块 CMake 文件。

```powershell
cpkg sync --offline
cmake --preset Debug
cmake --build --preset Debug
cmake --preset Release
cmake --build --preset Release
```

M2006 使用单独构建目录，避免覆盖默认电机固件：

```powershell
cmake -S . -B build/Debug-M2006 -G Ninja -DCMAKE_BUILD_TYPE=Debug -DCMAKE_TOOLCHAIN_FILE=cmake/gcc-arm-none-eabi.cmake -DMOTORCONTROL_USE_M2006=ON
cmake --build build/Debug-M2006
```

## 软件回归测试

测试运行原应用、串口解析器、PID、DJI 和 bxCAN 发送层，只有 HAL/RTOS 由确定性替身提供。
不创建真实串口连接，不驱动电机。测试产物保存在临时目录，结束后清理。

```powershell
python tests/run_host_tests.py --compiler "D:/mingw64/bin/g++.exe"
```

该命令分别检查 M3508 和 M2006，覆盖杂字节、CRC、粘包、DMA 环绕、故障重连、
急停确认、超时、限流、PID 重置、停留计时、反馈饱和及 CAN 队列清理。
测试中手工重新标零只用于隔离测试用例，生产程序不会在故障重连时自动重新标零。

## 仍需实机验证

1. 手动正反转，核对输出轴正方向、减速比、上电零点和跨圈连续性。
2. 上位机周期发送、杂字节注入及拔插；检查 DMA 持续收发、LED0、400 ms 断联停机和急停确认。
3. CAN 拔插、无应答、总线恢复和发送拥堵；检查旧电流撤销、持续零输出及位置无效锁定。
4. 用较小电流开始，分别验证 200/0 rpm 方波、负载扰动、位置超调及速度/位置模式切换。
   PID 参数没有凭软件测试宣称已调好。
5. 两套预设动作全程录像，特别检查在 720°/360° 停留时受扰后的重新计时及最终停稳状态。
6. 示波器/调试器检查 1 kHz 控制周期、最大中断延迟、任务栈水位及实际急停停转距离。
   单圈编码器展开仍要求相邻有效反馈转角小于 180°；高速丢帧时应专项验证。

梯形/S 曲线仍属未接入的选做功能。
